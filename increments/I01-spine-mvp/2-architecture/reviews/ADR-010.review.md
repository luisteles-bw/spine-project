## Summary
ADR-010 is a faithful record of the human's T10 decisions (`sessions/S01-2026-11-22.md:81-83`, Decisions
row 10 line 47) plus the 2026-11-23 amendment and the 2026-11-24 ADR-018 amendment. The decision itself is
not re-reviewed. Two problems matter: the ADR's whole role model rests on the hook input carrying
`agent_type`, and current Claude Code docs confirm that field exists but also show it is **optional and
known to go missing inside a running subagent** — a gap the ADR's "no agent_type = main session, unknown =
read-only" fallback turns into a scope-escalation path, and which P01 does not probe. Separately the ADR
cites a **60 s** hook timeout that the current docs no longer state (default is 600 s, 30 s in some
contexts), and two amendment facts (`~/.claude/**` deny vs `disableAllHooks`; `agent_type` == role) have
drifted from the documented mechanism.

| 1 | blocker | The role model keys on `agent_type` and treats **absent** `agent_type` as the main session and **unknown** as read-only (ADR-010:27, 37-38). Claude Code's own docs mark `agent_type` as "Present **when** … the hook fires inside a subagent" (optional), and a known, still-unresolved bug reports `PreToolUse` inside a *running subagent* sometimes arriving with **no `agent_type`** (anthropics/claude-code #90662, macOS, CC 2.1.251, closed not-planned 2026-10-31). A scoped subagent whose `agent_type` is dropped would be read by the guard as the **main session** — which may write nothing to `code/**` (so a coder tool call gets wrongly denied), or, worse if the main-session branch is ever loosened, mis-scoped. Either way the guard's identity premise is not reliable, and the "fail closed" claim does not hold when the *missing* input silently reclassifies the actor. | `ADR-010:27,37-38`; https://github.com/anthropics/claude-code/issues/90662 ; https://code.claude.com/docs/en/hooks (agent_type "Present when … the hook fires inside a subagent") | Have P01 probe #90662 directly on the pinned CC version: fire a scoped subagent and assert every `PreToolUse` it makes carries the expected `agent_type`; re-plan if it ever arrives absent. Until proven, state the fallback explicitly: a scoped step is active in `active.json`, so a tool call with **no** `agent_type` while a scoped role is active must be **denied** (not treated as main-session), because the real actor is ambiguous. Record the CC version the behaviour was verified against. | fixed: ADR-010 v4 (unified deny rule: absent or mismatched `agent_type` while scoped role active = denied); P01-T04 v2 AC-4 added (verify CC #90662 not present, record CC version) |  |
| 2 | major | Stale external fact: the ADR says the guard runs its own deadline "not relying on the **60 s** hook timeout" (ADR-010:63-64). Current CC docs state the default `command`-hook timeout is **600 s** (lowered to 30 s on `UserPromptSubmit`/`PreModelSwitch`/`PostModelSwitch`), not 60 s. The decision to self-deadline is sound, but the cited figure is wrong and would mislead whoever tunes the budget. | `ADR-010:63-64`; https://code.claude.com/docs/en/hooks (timeout defaults 600 command / 30 in some contexts) | Replace "60 s" with "CC's command-hook timeout (600 s default, 30 s in some contexts)" or just "CC's hook timeout"; keep the self-deadline rationale. | fixed: ADR-010 v4 (timeout updated to "600 s default, 30 s on some hook types") |  |
| 3 | major | The amendment claims denying Edit/Write on `~/.claude/**` stops an agent slipping `disableAllHooks` into user settings (ADR-010:69-70). Per current docs `disableAllHooks` lives in a settings file **and** can be forced for one run via `--settings '{"disableAllHooks": true}'`, which "takes precedence over project and local settings." The `~/.claude/**` deny covers the file path but not the CLI/flag route, and the hook deny is itself only installed at switch-over (I01-PLAN:143). So the stated control is partial; the ADR presents it as closing the hole. | `ADR-010:69-70`; https://code.claude.com/docs/en/hooks (`disableAllHooks`; `--settings` precedence); `I01-PLAN:143` | Reword to "the `~/.claude/**` deny blocks the *file* route; the `--settings` CLI route is out of the agent's reach only because the agent cannot launch its own CC process — state that assumption." Confirm against the P01 settings probe. | fixed: ADR-010 v4 (deny covers file route; CLI flag route blocked by Bash allowlist since agents can't launch their own CC process — assumption stated explicitly) |  |
| 4 | minor | Fidelity drift on the "Hooks run outside the sandbox with full user access" premise (ADR-010:17-18, 66). This is load-bearing (it is why `tool_input` is untrusted and why `~/.claude` is denied) but is asserted with no source and was not on the P01 probe list (I01-PLAN:31,161 probe sandbox/exit-2/agent_type/network, not "hooks run unsandboxed"). If a future CC version sandboxed hooks, several claims here shift. | `ADR-010:17-18,66`; `I01-PLAN:31,161`; CC hooks docs do not state hooks are sandboxed either way | Add "hook process runs unsandboxed with the user's access" to the P01 probe list, or cite the CC doc line that states it; mark it "unverified" until then. | fixed: P01-T04 v2 AC-5 added (verify hook can read /etc/hosts, confirming unsandboxed access) |  |
| 5 | minor | The ADR says a mismatch `agent_type != active.json.role` is denied as a "stale/mismatched subagent" (ADR-010:39-41), and that one scoped role is active at a time. This is correct given a reliable `agent_type`, but combined with finding 1 it has a sharp edge the ADR does not name: if `agent_type` is *absent* the equality test `undefined == active.json.role` is false, so the write is denied — which is the safe outcome, but only by accident, and the ADR's prose attributes the denial to the main-session branch (read-only), not to the mismatch rule. The two branches disagree about *why* an absent-`agent_type` scoped write is refused. | `ADR-010:37-41` | State one rule: while a scoped role is active in `active.json`, any write-capable tool call whose `agent_type` is absent or `!= active.json.role` is denied. Remove the ambiguity between the "main-session = read-only" and "mismatch = denied" branches for the absent case. | fixed: ADR-010 v4 (unified deny rule covers both absent and mismatched cases; combined with F1 fix) |  |
