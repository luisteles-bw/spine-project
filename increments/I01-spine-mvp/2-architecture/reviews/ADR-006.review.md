## Summary
ADR-006 is faithful to the recorded T6 decision on all the load-bearing points (seq=line-position,
additive-only types, per-record SHA-256, hand-rolled `O_EXCL` lock, dead-pid staleness, torn-line
repair human-only, single-machine assumption) and its three external-tool claims (`O_EXCL`,
`process.kill(pid,0)`, the `proper-lockfile` rejection) all verify against current docs. The one
real fidelity gap is `actor`: the recorded decision says "from shell detection", the ADR now says
"from the writing binary". The change is correct (shell detection is not a boundary — ADR-012), but
the originating decision record (session-log T6) was never reconciled, so the two now contradict.
A second, minor gap: ADR-006 narrows ADR-005 ("records are write-once") but ADR-005 was not updated
to point back.

## Areas with no findings
- **Event shape & identity.** `{seq, ts, type, node, actor, payload}`, `seq` = line position, gap/dup/`seq≠position` = hard stop (exit 3) matches the recorded decision (S01:71) and architecture.md:64.
- **Additive-only types.** Consistent with ADR-004's additive-only evolution (ADR-004:38-40); replay of old logs is preserved.
- **`ts` from the injected clock.** Consistent with the pure-core/injected-ports rule (ADR-001:37-41, conventions.md "Core is pure").
- **Derived `graph.json`.** Pure reducer, deterministic serialize, no generated-at timestamp, write-only / never read for a decision — matches ADR-005:52-53 and architecture.md:64,66 and protects REQ-010.
- **`O_EXCL` lock.** Verified: the Node.js fs 'x'/O_EXCL flag returns an error if the path already exists, giving the needed atomic exclusive create. (https://nodejs.org/api/fs.html#file-system-flags)
- **Stale-lock detection via dead pid.** Verified: `process.kill(pid, 0)` tests process existence without sending a signal and throws if the process does not exist; using it (not a time expiry) avoids stealing a live lock. (https://nodejs.org/api/process.html)
- **`proper-lockfile` rejection.** Verified: proper-lockfile updates the lockfile's `mtime` on a timer (`stale`/`update` options) and is aimed at long-running holders — so the rejection rationale is accurate. (https://github.com/moxystudio/node-proper-lockfile)
- **Critical-section discipline.** "Hold the lock only around read→validate→append→write graph→commit; re-read last seq under the lock" matches S01:73 and is consistent with ADR-009's one-git-writer model.
- **`active.json` written inside this lock.** ADR-010:33-34 writes `active.json` inside "the same ADR-006 lock" carrying the event `seq`; consistent, no drift.
- **Recovery.** Torn final line = human-only repair; interior corruption = hard stop (exit 3). The `repair` command is in the human-only `spine-admin` binary (ADR-012:26), so the "human-only" claim holds.
- **Enforcing SEC-002.** ADR-006 correctly defers the settings list and its baseline-vs-switch-over timing to ADR-012 + the plan table (ADR-006:50-56); it does not restate or contradict them, and `failIfUnavailable:true` being baseline (plan.md:128) vs the state/git `denyWrite` being switch-over (plan.md:141) is coherent because ADR-006 defers timing.
- **State directory layout cross-reference.** `project/state/**` glob, committed `events.jsonl`/`graph.json`, gitignored `.lock` (architecture.md:143-150) are consistent with ADR-006; the ADR correctly leaves the layout to architecture.md.
- **Import/switch-over linkage.** ADR-016:34 ("import hashes every existing record, so record immutability starts at switch-over") matches ADR-006; `source: bootstrap-import` actor (ADR-006:33-34) matches ADR-016:26-27.
- **No event hash chain in MVP.** Stated as deliberate deferral (ADR-006:48); not a gap given per-record hashes + the `project/` git second audit trail.
