## Summary
The architecture is coherent, the security model is defence-in-depth rather than single-layer, and the
P01 spike is the right gate before building on unverified harness behaviour. The central weakness is that
the whole boundary rests on Claude Code sandbox keys, and two of the key **names** written throughout the
documents are wrong against the current docs: `excludedCommands` must be `sandbox.excludedCommands`
(blocker — a top-level key is silently ignored, which fails the boundary open), and the
`strictAllowlist` key path the documents still mark "pending" is in fact resolved in the current docs as
`sandbox.network.strictAllowlist`. Several phase numbers in the P01 task files are stale after the
15-phase renumber. The ADR-012 review already fixed the *scope* problem (workspace vs user settings); the
key-name problem is separate and still live.

## Areas with no findings
- **Fact-checking of outside claims.** `@anthropic-ai/sandbox-runtime` is Apache-2.0 and a research preview (verified; the design pins it and gates it, ADR-011). PreToolUse exit-2-only blocking, `agent_type` presence in subagent hook input, hook timeout defaults (600 s command / 30 s prompt), `sandbox.allowUnsandboxedCommands`/`failIfUnavailable` semantics, and the `sandbox.filesystem.denyWrite`/`denyRead` + `allowRead` narrower-path rule all match the current docs. Twenty's free self-hosted plan offering custom objects/fields/views with the TypeScript app SDK, and row-level permissions being a paid-plan feature, are both confirmed.
- **Event-log integrity model (ADR-006).** `seq` = line position with gap/duplicate hard-stop, per-record SHA-256 at submit, O_EXCL stale-pid locking, write-once records, deterministic timestamp-free `graph.json` — sound; REQ-010 replay-stability is testable and planned (P04).
- **phase_pr tamper-proofing (ADR-009).** Head-SHA-equals-approved-SHA plus `merge-base --is-ancestor` rejects squash and post-review pushes without needing server-side branch protection; the Free-plan branch-protection caveat is correctly stated.
- **Plan coverage.** Every Must requirement maps to a phase (coverage table, `plan.md:98-116`); phase estimates are all ≤ 24 h and the split limits are self-applied; the P11 milestone ordering serves the Dec-13 goal; the parallel human track (H0–H3) lists the human steps including the pre-P01 machine-level settings block. The schedule verdict is honest about P01–P11 not all landing by the 13th.
- **Review gate wiring (ADR-018 / REQ-090).** The `stage_exit` precondition (topic + adr + stage reviews, each finding with a Response) and the design-reviewer blind-read deny on `topics/*.architect.md` (REQ-091, guarded per ADR-010) are consistent across the plan, requirements and the guard policy.

## Decisions (human, 2026-11-25)
Recorded when the human reviewed the Responses above. F3 is also in its Decision cell; the other two are
corrections the human raised from the CC settings reference that are not tied to a single finding.

1. **F3 — `sandbox.credentials` mode.** Confirmed: `mode: "deny"` in the workspace tier; **no masking**,
   now or as a future option. Check secrets are injected per-check by spine's `@anthropic-ai/sandbox-runtime`
   wrapper (ADR-011), a layer separate from Claude Code's agent-session sandbox.
2. **D7 rationale (relates to F1/F2).** The three machine-level sandbox keys (`sandbox.excludedCommands`,
   `sandbox.allowUnsandboxedCommands`, `sandbox.failIfUnavailable`) have scope **"Any file"** per the CC
   settings reference. They stay at user level for **precedence + coverage** — a user-level `false` holds
   against a project `true`, and one user file covers every workspace — **not** because a workspace file
   ignores them. Only `sandbox.network.strictAllowlist` (User or managed) and credential masking are truly
   user/managed-only. Amend the rationale wording only; **no placement change**. Applied: ADR-012 v6,
   SEC-007 (security.md v7), plan.md v5 H0 rows.
3. **`disableAutoMode` key placement.** It is a **top-level** key, not under `permissions`. Use top-level
   `disableAutoMode` and `permissions.disableBypassPermissionsMode`. Added to P01-T05 (v5): run
   `claude doctor` with the full settings and confirm it rejects no entries (AC-5). Applied: ADR-012 v6,
   security.md v7, plan.md v5, P01-T05 v5.
