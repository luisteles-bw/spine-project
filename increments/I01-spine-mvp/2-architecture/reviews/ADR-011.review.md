## Summary
ADR-011 is a faithful record of the T11 decision (S01:48, S01:84–86): every sub-decision — sandbox-runtime
containment, network deny-by-default + per-check allowlist, least-privilege secrets, post-check sweep,
keychain-unreadable test, direct-tool checks, Vitest JSON + per-criterion `AC-n`, keychain adapter + WSL
fallback, exact+base64+URL redaction, <8-char refusal, Bash-deny `security`/`secret-tool` — appears. The
external facts verify (Apache-2.0, research preview, Seatbelt/bwrap, network model, Vitest JSON status).
The one substantive gap is that the keychain-unreadable guarantee rests on sandbox-runtime's **default**
Seatbelt/bwrap profile denying the keychain's Mach services, which the spine does not control and the ADR
does not state as a dependency — see F1.

| F1 | major | The keychain-unreadable claim rests on a fact the ADR neither states nor controls. On macOS, `security find-generic-password` reaches the keychain through `securityd` over Mach/XPC, not a file read — a sandbox that only fences the filesystem and network does **not** block it; the keychain is closed only if the active Seatbelt profile denies the `com.apple.securityd`/`com.apple.SecurityServer` Mach services. ADR-011 both forbids hand-written profiles ("No hand-written Seatbelt/bwrap profiles") and relies on sandbox-runtime's default profile for this, so the whole guarantee hinges on a default the spine can't see or set. The ADR hedges with a test ("If it can, this ADR needs another answer") but states no fallback. | ADR-011:25–26 (no hand-written profiles), 36–37 (keychain test); macOS Seatbelt keychain-via-Mach behaviour per https://github.com/anthropics/sandbox-runtime and community Seatbelt profiles (keychain closed only by `(deny mach-lookup com.apple.securityd …)`), see discussion at https://github.com/anthropics/sandbox-runtime | Add one sentence to the Decision: the keychain test is a **release blocker**, and if sandbox-runtime's default profile does not deny the keychain Mach services the fallback is to not inject keychain secrets into sandboxed checks (keep the `build` token out of the sandbox / supply via an env store the sandbox denies-read), rather than "needs another answer". ## Areas with no findings
- **Fidelity to the T11 decision.** Every element of the recorded decision (S01:48, 84–86) is present in ADR-011 with no additions or contradictions, including the `test`-gets-no-secrets / `build`-gets-only-CMS-token split, the post-check sweep, direct-tool argv, Vitest JSON + per-criterion `AC-n`, WSL 0600 fallback, and <8-char refusal.
- **External facts.** `@anthropic-ai/sandbox-runtime` is Apache-2.0 and a research preview; macOS uses `sandbox-exec`/Seatbelt, Linux uses bubblewrap; network is deny-by-default with per-command `allowedDomains`/`deniedDomains`. Verified at https://github.com/anthropics/sandbox-runtime and https://www.npmjs.com/package/@anthropic-ai/sandbox-runtime.
- **Vitest JSON claim.** The JSON reporter records `status: "passed" | "failed" | "skipped" | "todo"` per test, so "a skipped test is not a pass" is sound. Verified at https://vitest.dev/guide/reporters and https://github.com/vitest-dev/vitest/issues/2417.
- **No-shell / argv form.** `["pnpm","exec","vitest","run"]` via `execFile` is valid and consistent with SEC-009 and ADR-010's tripwire.
- **Architecture/plan alignment.** architecture.md:49 (process adapter → sandbox-runtime), 118 (ADR-011 summary), and I01-PLAN:37/74 and the settings table (plan.md:135–138) carry the ADR-011 controls consistently.
