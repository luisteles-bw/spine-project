## Summary
ADR-012 is faithful to the recorded T12 decision and the D1/D2/D6 amendments, and its impact is
mostly reflected in SEC-001/002/007/019/020, REQ-013 and the plan's settings table. But the central
mechanism rests on two Claude Code facts that the current docs contradict: the hardened sandbox keys
the whole boundary needs (`allowUnsandboxedCommands: false`) and the `excludedCommands: ["spine *"]`
exclusion are **ignored when set in a workspace/project settings file** — exactly where ADR-012 says
`spine-admin init/upgrade` installs them. That is a blocker because it voids both the human-only
boundary and the "only `spine` writes state" model. One stale key name (`sandbox.network: none`) is a
minor fix.

| F1 | blocker | `allowUnsandboxedCommands: false` **does not take effect from a workspace/project settings file**. ## Areas with no findings
- **Fidelity to the T12 decision.** The OS-enforced `spine-admin` boundary, rejection of env-var/TTY as the check, three-binary split, Bash `deny spine-admin *`, y/N+hash as UX only, package-sourced templates + diff, and the two ordering rules (baseline-`failIfUnavailable` now; guard hook only after `spine-guard` exists) all match S01:87-88. The 2026-11-23 amendments (`import` added; `sandbox.network` per D2; dependency-install denies per D6; shell-rc denies for SEC-020; `git add/commit/switch` allowed until switch-over per D1) match the recorded D1/D2/D6 decisions and the STATE.md log.
- **`repair` in the human-only list.** Not in the T12 entry but established human-only by ADR-006 (T6: "torn-line repair is human-only", S01:71; ADR-006:68); including it is correct and consistent with `architecture.md:31`.
- **`excludedCommands` still follows permission rules.** ADR-012:62 ("excluded commands still follow permission rules") matches current docs — excluded commands run unsandboxed but still pass allow/ask/deny. `ask` before `allow` ordering (line 61) is also correct per the docs.
- **Impact on security.md / requirements.md.** SEC-001/002/007/019/020 and REQ-013 are present and consistent with the ADR's wording (subject to F1/F2, which also touch SEC-007/REQ-050). `disableBypassPermissionsMode` and `disableAutoMode` are real keys with "Any file" scope, so those two (line 68) are fine from the workspace file.
- **Phase timing.** Phase numbers were removed from the ADR (per the 2026-11-24 pass) and deferred to `I01-PLAN`'s ADR→phase table (P02 baseline + P10 switch-over); the stale S01:121 "P04/P05" note is superseded by the plan, so no live contradiction in the ADR.
