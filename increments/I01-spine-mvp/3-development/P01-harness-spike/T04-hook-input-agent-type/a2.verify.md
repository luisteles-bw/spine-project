## Summary

AC-3 passes on attempt 2. The re-run of `curl -sS --max-time 5 -v https://example.com` delivered six machine-readable evidence strings confirming that `sandbox.network.strictAllowlist: true` is effective on Claude Code v2.1.325: the srt proxy returned `HTTP/1.1 403 host is not on the allow list`, curl exited 56, and a `<sandbox_violations>` block was emitted — all without any interactive per-domain prompt. No key-path change to ADR-011 is needed. AC-1, AC-2, AC-4 and AC-5 were judged pass in a1; they are carried here unchanged. T04 is fully verified across a1 + a2.

## AC-3 evidence record

The re-run transcript is at `probes/agent-type/output/ac3-network-rerun.txt`.

**Sandbox proxy identification.** `https_proxy == 'http://srt.dG9vbH...@127.0.0.1:49725'` — the `srt.` username prefix identifies the proxy as the sandbox-runtime (srt) proxy, the same runtime ADR-011 relies on for check secret injection (see finding (b)).

**Deny response.** The CONNECT tunnel negotiation returned:

```
< HTTP/1.1 403 host is not on the allow list
< X-Proxy-Error: blocked-by-allowlist
* CONNECT tunnel failed, response 403
curl: (56) CONNECT tunnel failed, response 403
curl exit=56
```

**Sandbox violation record.** Immediately after the curl output:

```
<sandbox_violations>
deny network-outbound example.com:443 (host is not on the allow list)
</sandbox_violations>
```

**No per-domain prompt appeared.** The only approval interaction in this attempt was the generic Bash command-approval prompt (operator-reported; see finding (a)). After that single approval, the srt proxy still denied the connection — the network deny is enforced by the proxy, independent of the permission-approval layer.

## Findings

**(a) Two-layer permission model.** The curl invocation triggered a Bash command-approval prompt under `--permission-mode default`, whereas the earlier `echo` calls did not (operator-reported; the PNG meant to document this is the wrong image and is excluded — see Issues). Crucially, this approval layer does not control the network: attempt 1 (operator declined → curl never ran) and attempt 2 (operator approved → curl ran and was proxy-denied) together show that the srt-proxy allowlist enforces network isolation independently of the command-approval gate.

**(b) srt-proxy is the sandbox-runtime proxy.** The `srt.` prefix in the proxy credentials (`http://srt.dG9v…@127.0.0.1:49725`) is the sandbox-runtime identifier. This confirms the agent Bash sandbox and the ADR-011 check secret-injection mechanism share the same srt runtime boundary — an architectural confirmation that the check runner's isolation model is consistent with what the guard will face at D2.

## Posture confirmation

`ac3-launch.txt` records `claude --model sonnet --permission-mode default` (Claude Code v2.1.325). This matches the a1 posture record. All five a1 hook payloads carried `"permission_mode":"default"` (5/5 firings); the a2 re-run was launched under the same command. The session ran under the hardened default posture throughout.
